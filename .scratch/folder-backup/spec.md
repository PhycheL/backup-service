## Problem Statement

我需要把若干自己指定的文件夹，按天打成压缩备份，放到自己指定的位置。机器常开时到点自动打；没开就跳过，开机不要补打。备份要能留大约一个月的份数，旧的可以丢掉。我还要一个本机页面，能建任务、看日志、手动补打一份。代码写在这个仓库里，但被备份的不是这个仓库。

## Solution

在 Mac Studio 上跑一个常驻的文件夹备份服务。每个**任务**锁死一个**备份源**和一个**备份目标**，并有自己的**计划时刻**（不配则默认凌晨 3 点）。到点为未**停用**的任务打一份独立的 tar.gz **归档**；人也可以在**操作台**对某条任务**手动备份**。每条任务最多留 30 份完整归档。操作台只在本机浏览器打开，不做恢复、不写回备份源。

## User Stories

1. As a 本机使用者, I want 在操作台新建一条任务并指定备份源和备份目标, so that 之后的归档都按这份指定来打，而不用每次再选目录
2. As a 本机使用者, I want 新建任务时可以不填计划时刻, so that 我不配也能每天凌晨 3 点自动打
3. As a 本机使用者, I want 新建任务时可以为该任务指定别的计划时刻, so that 不同文件夹可以在不同钟点备份
4. As a 本机使用者, I want 已开始的任务不能改备份源或备份目标, so that 一条任务里的归档始终对应同一对目录
5. As a 本机使用者, I want 换源或换目标时必须新建任务, so that 旧任务的归档不会和另一套目录混在一起
6. As a 本机使用者, I want 在操作台改某条任务的计划时刻, so that 我不必为了改钟点而开新任务
7. As a 本机使用者, I want 同时存在多条任务, so that 我可以备份多个文件夹
8. As a 本机使用者, I want 多条任务互不影响执行顺序, so that 我不必安排谁先谁后
9. As a 本机使用者, I want 每条任务使用自己的备份目标, so that 清一份过期归档时不会碰到另一条任务的包
10. As a 本机使用者, I want 新建任务时备份目标必须是已存在的完全空目录, so that 新任务的保留份数不会回收别人留下的包
11. As a 本机使用者, I want 若备份目标不存在、不是目录、或里面已有任何文件或文件夹则创建失败并看见原因, so that 我不会把包打进错误的位置
12. As a 本机使用者, I want 停用一条任务, so that 它不再参加自己的计划时刻，也不能再手动备份
13. As a 本机使用者, I want 重新启用一条已停用的任务, so that 它从下一次自己的计划时刻起再自动打
14. As a 本机使用者, I want 删除一条任务, so that 操作台上不再出现它，也不再自动或手动打
15. As a 本机使用者, I want 停用、启用、删除都不碰备份目标里已有的归档, so that 我不会因为整理任务而丢掉已经打好的包
16. As a 本机使用者, I want 停用期间不记漏次, so that 日志不会把「故意不跑」写成「错过了」
17. As a 本机使用者, I want 每天在某条未停用任务的计划时刻自动尝试打一份归档, so that 我不用记得去点备份
18. As a 本机使用者, I want 计划时刻那一轮最多试 3 次、两次之间约 1 分钟, so that 目标盘短暂未就绪时还有机会打成
19. As a 本机使用者, I want 3 次都未成则该轮失败、不写半包、不占保留份数, so that 坏掉的尝试不会冒充一份归档
20. As a 本机使用者, I want 下一次该任务的计划时刻重新给 3 次尝试, so that 昨天失败不会扣掉明天的机会
21. As a 本机使用者, I want 计划时刻机器未开机时该任务记一次漏次并且不打归档, so that 日志能反映错过，但开机后不会突然补打
22. As a 本机使用者, I want 漏次相对的是该任务当时配置的计划时刻, so that 改过钟点的任务不会按别人的钟点算错过
23. As a 本机使用者, I want 开机或服务重新起来时不补打归档, so that 「只在计划时刻打」仍然成立
24. As a 本机使用者, I want 在操作台上对未停用任务点一次手动备份并立刻看到结果, so that 我改完文件可以马上留下一份
25. As a 本机使用者, I want 手动备份只试 1 次, so that 失败时不必干等重试
26. As a 本机使用者, I want 手动备份打出的就是归档, so that 恢复时不必区分「手动包」和「计划包」
27. As a 本机使用者, I want 当天已经有计划归档后仍能再手动打一份, so that 下午改过的源也能留下
28. As a 本机使用者, I want 手动备份计入该任务的保留份数, so that 30 份上限对所有完整包一视同仁
29. As a 本机使用者, I want 停用中的任务无法手动备份, so that 「停用」就是这条任务现在不要再产生归档
30. As a 本机使用者, I want 同一任务同一时间只能有一份归档正在产生, so that 不会并行打出半包或几乎相同的两份
31. As a 本机使用者, I want 后到的计划或手动立即失败并写入日志, so that 我马上知道这次没打成，而不是在排队
32. As a 本机使用者, I want 不同任务可以同时打归档, so that 一条任务的长时间打包不会挡住另一条
33. As a 本机使用者, I want 每条任务最多保留 30 份完整归档, so that 磁盘不会无限涨
34. As a 本机使用者, I want 只有打出第 31 份完整归档时才删除该任务最旧的一份, so that 人动任务时不会误删包
35. As a 本机使用者, I want 漏次和失败不占保留份数, so that 空窗不会把更早的好包留下来凑数，也不会把失败当成一份
36. As a 本机使用者, I want 一条任务的过期删除不影响其他任务, so that 各任务的 30 份是分开的
37. As a 本机使用者, I want 归档是完整 tar.gz 而不是增量链, so that 任意一份都可以单独解开，删旧包不影响剩下的
38. As a 本机使用者, I want 自己到备份目标用系统工具解开归档, so that 操作台不必做恢复、也不必写回备份源
39. As a 本机使用者, I want 打到一半留下的半包在该任务下次尝试开始前被清掉, so that 残文件不会冒充归档或占目录
40. As a 本机使用者, I want 半包不计入保留份数, so that 30 份里都是打得开的包
41. As a 本机使用者, I want 在操作台看到每条任务的日志（计划尝试、手动备份、失败、漏次）, so that 我知道最近几次发生了什么
42. As a 本机使用者, I want 登录后服务自动起来, so that 我不必每次开终端跑命令
43. As a 本机使用者, I want 用本机浏览器打开操作台, so that 启动就是收藏一个地址
44. As a 本机使用者, I want 操作台只听 127.0.0.1 并且不用登录, so that 局域网里其他人进不来，我自己又不必记口令
45. As a 本机使用者, I want 任务和日志存在系统 Application Support 的 SQLite 里, so that 备份目标目录里只有归档
46. As a 本机使用者, I want 已删除任务留下的归档继续留在原备份目标, so that 「删除任务」不等于清盘
47. As a 本机使用者, I want 不能把已有内容的目录指定为新任务的备份目标, so that 新任务的第 31 份不会删掉旧任务留下的包
48. As a 开发者, I want 用 Go 单二进制交付这个服务, so that 启动不依赖 Python venv 或 Node
49. As a 开发者, I want 操作台用 Go 模板出 HTML, so that 没有前端构建步骤
50. As a 开发者, I want 计划时刻由常驻进程按每条任务自己的钟点触发, so that 不必再挂一条 launchd 日历任务

## Implementation Decisions

- 本仓库新增一个并列的 Go 程序（与现有 Python 剪贴板工具无关）。运行形态见 ADR `0001-go-local-daemon`：单二进制、LaunchAgent 登录拉起、进程内调度、Go 模板操作台、只绑 `127.0.0.1`、SQLite 放在 `~/Library/Application Support/`、归档为 tar.gz。
- 对外只暴露一个应用：任务的新建/停用/启用/删除、按任务改计划时刻、手动备份、走到某任务的计划时刻。HTTP 操作台和 LaunchAgent 是适配器，不成为第二套规则。
- 计划时刻存在每条任务上。新建时省略则写默认 `03:00`（机器本地时区）。操作台可改已开始任务的计划时刻；源和目标仍不可改。
- 每条未停用任务每个本地日历日最多一轮计划尝试。若当天该轮尚未开始，改钟点后按新钟点等到点再开轮；若当天该轮已开始或已结束，不再为新钟点开第二轮。不追溯已经过去的钟点，也不因改钟点立刻打归档。
- 进程在某条未停用任务的计划时刻当时不在（机器未开或服务未起）则记漏次、不打归档。服务随后起来时可以为已经错过的日期补记漏次，但不得补打归档。
- 计划一轮内对该任务最多 3 次产生归档的尝试，间隔约 1 分钟；3 次都失败则该轮失败。手动备份对该任务只尝试 1 次。
- 同一任务同一时间只允许一次「正在产生归档」。后来者立即失败并写日志，不排队。不同任务可以并行。
- 产生归档前先清掉该备份目标里属于半包的残文件。只有完整 tar.gz 才是归档。打出第 31 份完整归档时，删除该任务最旧的一份完整归档；不得删除其他任务的文件，也不得删除半包之外、不属于归档的无关文件（目标在创建时为空，之后只应出现本任务写下的文件）。
- 新建任务时校验：备份源必须是已存在的文件夹；备份目标必须是已存在的完全空目录。任一不满足则任务不建立。
- 删除任务只删除应用里的任务记录和调度，不删除备份目标中的文件。删除后操作台不再列出该任务。
- 操作台不提供解压、写回备份源、或挑选恢复目标。不提供局域网访问、鉴权、增量链、zip/ditto。

## Testing Decisions

- 好测试只看外部行为：给定任务与钟点、注入的时间、源目录内容和目标目录初始状态，调用应用的操作后，断言目标里的归档/半包、任务是否仍存在、源和目标有没有被改写、日志是成功/失败/漏次、以及第 31 份出现时最旧归档是否被删。不测 HTTP 路由表、SQL 语句、LaunchAgent plist 文本、或 tar 的内部实现细节。
- 全仓库只测一条缝：备份应用。测试通过它的操作驱动（新建/停用/启用/删除任务、改计划时刻、手动备份、推进到计划时刻），时钟、工作目录、压缩过程可注入。HTTP 与 LaunchAgent 不另开测试缝。
- 本仓库目前没有测试先例；这是第一条缝，也是第一个测试面。

## Out of Scope

- 操作台恢复、写回备份源、从归档里挑文件还原
- 开机或服务启动时补打归档
- 局域网访问、口令、多用户
- 增量备份、zip/ditto、跨机器同步、云端目标
- 改已开始任务的备份源或备份目标
- 把网页做成独立前端工程
- 改动现有 Python 剪贴板监控工具

## Further Notes

- 领域词以仓库根目录 `CONTEXT.md` 为准。不要把「备份约定」「快照」「开机补做」「全局计划时刻」写回实现或文案。
- 实现选择以 `docs/adr/0001-go-local-daemon.md` 为准。
- 计划时刻是每条任务自己的钟点，不是全场一个钟点。
