## 母规格

[规格：macOS 一次性多备份项 ZIP 备份程序](https://github.com/PhycheL/backup-service/issues/1)

## 要交付的行为

操作者为每个备份项设置保留份数。程序在该项新备份成功发布后，清理该项最旧的超额备份包；数量包含本次新包。多个备份项共用备份目录时各自保留最近的规定数量，互不影响，也不删除无关内容。

## 验收标准

- [ ] 每个备份项独立使用自己的保留份数，成功清理后的数量上限包含本次新生成的备份包；验证保留 1 份及不同项目使用不同数值的情况。
- [ ] 仅在当前备份项的完整新 ZIP 已成功发布后，才清理其超额旧包；按从旧到新的顺序淘汰，并始终保留本次成功的新包。
- [ ] 新备份的读取、压缩或写入失败时，不清理该项任何历史备份包。临时或未完成产物不计入成功备份数量。
- [ ] 共用备份目录时，仅清理能够识别为本程序为当前备份项生成的包，不删除其他备份项、普通文件、归属不明的 ZIP 或其他名称下的历史包。
- [ ] 保留份数与备份包归属不依赖将目录中所有 ZIP 视为受管文件；更改备份项名称视为新的归属，不自动清理原名称的历史包。
- [ ] 旧包删除失败时保留已成功生成的新包，明确报告清理错误且该项存在失败结果，继续后续项，整次运行最终非零退出。
- [ ] 成功汇总与清理错误汇总能区分“新备份生成失败”和“新包已成功但旧包清理失败”，不对尚未完成的清理报告成功。
- [ ] 通过多次真实命令行运行产生历史包，验证共用备份目录、独立计数、成功后清理、失败不清理、无关文件保持，以及清理失败后的后续项执行；不调用内部清理函数作为测试入口。
- [ ] 更新保留份数、备份项名称稳定性与清理失败处理的使用说明，保留 10 份仍作为示例，不擅自将其固定为全局默认值。
