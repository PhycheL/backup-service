## 拆分方案

1. **[#2：单个备份项完成一次 ZIP 备份](https://github.com/PhycheL/backup-service/issues/2)**。阻塞项：无。将整个源目录归档为可恢复 ZIP，包含普通文件、隐藏内容、空目录和符号链接本身；完成配置读取、结果输出、退出和失败时不发布正式包的完整闭环。[本地正文](01-single-backup.md)。
2. **[#3：多备份项顺序执行与失败汇总](https://github.com/PhycheL/backup-service/issues/3)**。阻塞项：#2。交付按顺序执行多个备份项、单项失败后继续、配置范围内的目录关系校验，以及完整结果汇总和退出码。[本地正文](02-multiple-backups.md)。
3. **[#4：按备份项保留最近的备份包](https://github.com/PhycheL/backup-service/issues/4)**。阻塞项：#3。交付各项独立的保留份数和成功后清理，共用备份目录时不影响其他项或无关文件，清理失败也能继续后续项并报告。[本地正文](03-retention.md)。
4. **[#5：拒绝重复启动并自动释放运行锁](https://github.com/PhycheL/backup-service/issues/5)**。阻塞项：#2。交付已有实例运行时新实例立即退出，以及正常或异常结束后能够再次启动的完整生命周期。[本地正文](04-single-instance.md)。

## 本轮调整

用户指出应将父文件夹整体压缩，不应为符号链接另设功能。已将链接归档和恢复验收并入任务 1，不要求应用实现独立的链接处理模块。

已在隔离临时目录中验证：macOS 系统压缩工具通过保留链接选项，可以一次归档整个文件夹，并在解压后保留普通文件、隐藏文件、空目录和原始符号链接。

用户已确认由 Python 负责配置、调用、命名和结果处理，将整体压缩交给 macOS 系统自带的 zip 工具。该决策取代母规格中“由 Python 标准库生成 ZIP”的实现限定，记录于[架构决策 0002](../../adr/0002-system-zip-archiving.md)，并在第一张任务票中明确说明。恢复范围及保留链接、不跟随目标的约定保持一致。
