# 规格：macOS 一次性多备份项 ZIP 备份程序

## 问题陈述

用户需要在另一台 macOS 上运行一个文件夹备份程序。每次运行时，程序应读取已经配置好的多个备份项，依次将源目录压缩为 ZIP 备份包并写入对应的备份目录，然后结束进程。源目录与备份目录均可由运行程序的机器直接访问。

用户需要保留历史版本，同时控制每个备份项的备份包数量。单项失败不能阻止其他备份项得到处理，调用方需要通过汇总结果和退出码判断整次运行是否成功。重复启动也不能导致两个实例同时处理同一批备份。

## 解决方案

提供使用 Python 3 标准库实现的命令行备份程序。操作者维护一份配置，保存多个备份项的源目录、备份目录和保留份数。程序启动后按配置顺序执行，每个备份项生成独立、带时间戳的新 ZIP；该项新备份成功后，才清理该项超出保留份数的旧备份包。

备份包含普通文件、所有子目录、空目录、隐藏文件和符号链接本身。程序按照实际读取到的内容生成备份，不要求暂停其他程序的写入，不额外检测文件变化，也不额外保存 macOS 特有属性。恢复范围为普通文件内容、目录结构和符号链接。

每项处理后记录结果，失败时继续后续项。所有项目结束后统一汇总：全部成功返回退出码 0，任一项失败返回非零退出码。已有实例运行时，新实例提示“备份正在运行”，以非零退出码立即退出。

## 实现决策

### 已确认的决策

- 运行环境为另一台 macOS。使用 Python 3 标准库实现；当前开发机器的 Python 安装情况不能作为目标机器已具备运行环境的证据。
- 对外提供一次性命令行运行能力，不提供常驻请求监听。一次运行读取一份配置，按顺序执行其中的多个备份项。
- 每个备份项配置源目录、备份目录和独立的保留份数；源目录和备份目录由部署机器直接访问。
- 每次为每个备份项生成独立的 ZIP 备份包，文件名包含时间戳，不覆盖已有备份包。
- 完整遍历目录内容，包括隐藏内容和空目录。符号链接保存链接本身，不跟随文件链接或目录链接，不额外打包链接目标。
- 不要求源目录在压缩过程中保持不变，不锁定源文件，不进行备份前后的文件变化检测；实际文件读取或压缩错误仍应使该项失败。
- 不额外保存 Finder 标签、资源叉等 macOS 特有属性，不承诺同一时间点的一致性，也不承诺完整文件系统元数据恢复。遵循现有“使用 ZIP 保存文件级备份”的架构决策。
- 新备份成功后，才按从旧到新的顺序清理当前备份项超额的历史备份包。保留份数包含本次新备份包，各项独立计算、独立清理。
- 失败的备份项不触发该项历史备份清理，且不阻止后续备份项执行。整次运行结束后统一汇总，全部成功返回 0，任一项失败返回非零退出码。
- 同一台机器已有程序实例运行时，新实例立即输出“备份正在运行”并以非零退出码退出，不排队等待。

### 推荐的落实方式

以下内容来自先前讨论中的实现草案或对已确认行为的必要落实建议；它们是本规格的推荐默认值，不冒称用户已经逐项确认。

- 保持一个对外命令行入口。内部围绕配置读取与校验、单实例运行控制、单个备份项执行、旧包保留处理和结果汇总组织职责，无需引入服务、数据库或任务队列，也不预先固定内部文件拆分。
- 配置采用 JSON，启动时指定配置。顶层保存有序备份项列表；每项包含唯一且稳定的名称、源目录、备份目录和至少为 1 的整数保留份数。目录使用部署机器上的绝对路径。
- 备份项名称用于长期识别备份包归属，更改名称视为建立新的归属，原名称下的历史备份包不自动清理。不同备份项允许使用同一个备份目录。
- 备份包名称组合备份项名称、时间戳和防重名标识；即使短时间内多次启动，也不得覆盖已有包。包内保留源目录这一层目录。
- 只清理能够识别为本程序为当前备份项生成的完整备份包，不把目录中所有 ZIP 都视作可清理对象，也不依据普通文件修改时间推断备份包归属。
- 备份目录不存在时自动创建。源目录不存在或不可读取时，该项失败并继续后续项。拒绝备份目录等于任一已配置源目录或位于其内部的配置关系，判断时考虑实际路径，避免把输出再次纳入源目录。
- 压缩先写入临时产物；完整写入并成功关闭后才发布正式 ZIP，发布成功后才执行旧包清理。临时产物不计入保留份数，失败时尽力移除本次产生的临时产物。
- 清理失败时保留新备份，报告该项存在清理错误，继续处理后续项，最终返回非零退出码。不得为了满足保留份数而删除本次刚成功生成的新备份。
- 配置整体无法解析或备份项名称重复时直接报错退出；可独立归属到某一备份项的执行错误按单项失败处理。错误输出应明确指出受影响的备份项与原因。
- 以操作系统能够随进程结束释放的互斥机制实现单实例约束。进程结束后可再次启动，不依靠人工删除残留的“运行中”标志恢复工作；本规格不要求跨机器互斥。
- 终端输出每项的开始、结果、正式备份包位置和最终汇总，错误结果通过非零退出码交给调用方。不规定额外的机器可读结果协议。

## 测试决策

### 测试边界

用户已确认只通过命令行入口测试完整备份流程，不绑定内部函数。测试准备隔离的临时源目录、备份目录和配置，启动真实子进程，然后检查备份包内容、目录中文件的增删、终端输出和退出码。

没有现成的业务模块、测试套件或类似测试可以沿用。新增测试应通过命令行覆盖配置读取、备份执行、保留处理、单实例控制和结果汇总的外部行为，而不是分别建立与每个内部函数绑定的测试入口。

### 好测试的标准

- 断言使用者能观察到的结果，不断言私有函数名、内部调用顺序、精确模块拆分或日志排版。
- 使用真实且隔离的文件系统内容；通过独立读取备份包或实际解压检查结果，不复用实现中的遍历和筛选逻辑充当预期结果。
- 对符号链接检查链接类型和原始目标字符串，覆盖相对链接、绝对链接、目录链接与断开的链接；不只断言同名条目存在。恢复验证应使用支持 ZIP 中符号链接表示的工具。
- 通过程序入口制造可观察的失败条件，检查旧包和后续项，而不是仅验证某个内部方法抛出异常。
- 并发场景通过可观察的启动进展或外部进程控制进行协调，避免依靠固定等待时长碰运气。
- 首要验证平台为 macOS。测试自身使用临时目录，不接触操作者的真实备份。

### 必要场景

1. 首次运行：按顺序执行多个备份项，各自产生一个 ZIP，汇总成功并退出，退出码为 0。
2. 目录内容：普通文件、二进制内容、空文件、多层目录、空目录、隐藏文件及隐藏目录均正确纳入；覆盖含中文和空格的名称。
3. 符号链接：链接本身和目标字符串被保存，不进入链接目录，不把外部目标内容打包；断开的符号链接仍按链接处理。
4. 重复运行：连续运行生成不同名称的新包，已有包不被覆盖。
5. 保留份数：通过多次真实运行超过保留份数，只留下当前备份项最近的规定数量；数量包含本次新包。
6. 归属隔离：多个备份项共用备份目录，各自使用不同保留份数；无关文件、其他备份项的包和无法识别归属的 ZIP 均不被误删。
7. 单项失败：中间备份项的源目录不可访问时，该项无成功备份，历史备份保持，后续项仍运行，最终输出各项结果并返回非零退出码。
8. 不完整产物：压缩或写入失败时，不发布正式成功备份，不清理该项旧包；未完成产物不计入保留份数。
9. 清理失败：新备份保留，清理错误被报告，后续项继续，整次运行返回非零退出码。
10. 配置问题：配置不可解析、名称重复、保留份数不合法时给出明确错误；不存在的备份目录按推荐行为创建。
11. 目录关系：相同路径、备份目录位于任一源目录内部，以及路径别名指向上述关系的情况被拒绝，不能递归打包备份输出。
12. 重叠运行：第一个实例执行中，第二个实例立即提示“备份正在运行”并非零退出；第一个实例结束后，再次启动可以执行。
13. 恢复范围：验证文件内容、目录结构和符号链接；不把实时一致性或 macOS 特有属性的恢复作为通过条件。

## 范围之外

- 常驻服务、HTTP 接口、等待通知或程序内部定时调度。
- 并行执行多个备份项、跨机器分布式互斥。
- 文件上传、远程传输协议、云端存储接入；本规格以部署机器能直接访问目录为前提。
- 增量或差异备份、文件排除规则、按天数或容量淘汰历史备份。
- 暂停其他程序写入、源文件变化检测、文件系统快照和一致的数据库在线备份。
- 跟随符号链接复制目标数据、额外保存 Finder 标签或资源叉、完整文件系统元数据恢复。
- Windows 或 Linux 的兼容性验收。
- 图形界面、专用恢复程序和新增第三方运行依赖。
